# M1 相册实现

> 历史记录：保留当时的实现、界面和验收描述，不作为当前操作指南。
> 当前说明见[文档首页](../README.md)，归档目录见[历史索引](README.md)。

本页记录 0.2.0 的 M1 基线；0.3.0 已增加 [Wi-Fi 定时校时与 RTC UTC 迁移](../wifi-time.md)。ESP-IDF v5.5.3，Windows 原生构建。

## 已实现

- 加载 SD `/config.json` 和相册根目录清单，校验 schema、字段类型、范围、路径、重复键/ID、最大大小与嵌套深度。只扫描明确启用的目录，不递归。
- 文件名自然排序；默认逐相册播放，可选轮流取一张；随机队列每轮不重复，避免轮次边界重复，保存种子与游标。
- 24 位 BI_RGB、40 字节 DIB、正高度 BMP；六种精确 RGB 颜色；四种旋转；800×480 输出，192000 字节屏幕帧。尺寸/压缩/颜色不合规时跳过，不缩放或抖动。
- 完整屏幕初始化、刷新、BUSY 超时和结束关电；相同像素不重复刷新。
- BOOT 短按下一张、长按至少 2 秒深睡；KEY 唤醒并输出 RTC/温湿度诊断；PWR 保留 PMIC 硬件开关机行为。按键 40 ms 去抖；刷屏期间捕获按键，积累的多次短按合并一次。
- 刷新完成后开始完整停留间隔。手动成功换图重新计时；刷新失败不提交播放位置、不改变原截止时间，自动重试至少间隔 60 秒。
- 默认空闲 10 秒后深睡，BOOT/KEY 和定时器唤醒。正常深睡保留截止时间；完整重启恢复最后成功照片并重新开始完整间隔，不追补关机期间的换图。
- 独立 NVS 分区保存状态和最后验证通过的两份配置；SD 配置损坏时回退。首次无有效配置进入常醒恢复模式，修正 SD 后重启。原照片和用户配置不被应用改写。
- 每次刷新前写入 dirty 标志，刷新完成后提交位置并清除；中断刷新后恢复最后成功图并重新计时。正常保留图像的深睡唤醒不反复写 NVS。

## 使用

将 `sdcard/` 的配置模板复制到 SD，按清单目录放入预处理 BMP。默认示例仅启用 `family`，间隔 900 秒。`playback.enabled: false` 关闭自动推进，仍允许恢复照片与手动换图。

每份 JSON 最大 16 KiB、最多 64 个相册、合计最多 2048 张通过头部检查的图片；间隔 120–604800 秒。像素颜色在选中照片时完整检查。坏文件只在当前启动期间跳过，下一次启动重新检查。

修改配置后重启生效；不支持运行中热重载或 SD 热拔。全部没有有效照片时保留原图、停止自动换图，仍允许按键诊断和深睡唤醒。尚无屏幕错误菜单，错误原因输出到 USB 串口。

`CONFIG_EPAPER_IDLE_SECONDS` 设置常醒窗口；`CONFIG_EPAPER_CONFIG_PATH` 默认 `/config.json`。调整构建配置使用 `idf.py menuconfig`，参数在 “Epaper album” 中。

## 安装与数据

新分区 `album_state` 位于 `0x500000`，大小 `0x20000`。首次从原固件迁移前，核对 MAC、备份并校验完整 16 MB Flash，再单独初始化此分区；应用在 NVS 初始化失败时不自动擦除任何数据。更新相册固件时保留此分区。

在已激活 IDF 环境中，首次初始化命令为 `python -m esptool --chip esp32s3 -p COM5 erase-region 0x500000 0x20000`，随后 `idf.py -p COM5 flash`。仅在已经完成上述备份并确认分区布局时执行初始化。COM 号可变化。

原照片保留在 SD 原目录；示例配置只是清单，默认不扫描原固件的图片目录。Flash 原固件恢复需要写回完整备份，不能只写回应用区。

## 后续阶段

时间播报、串口校时与 UTC 迁移、音频片段、KEY 报时/静音、Wi-Fi、活动检测和低电量自动策略尚未实现。M1 拒绝启用 announcement/activity/Wi-Fi 或非 manual 同步；`power.low_battery_policy` 必须省略或为 `none`。

示例中的 device/time/sensor、关闭功能内部的设置为后续规格保留项，M1 不应用它们。特别是 `time.rtc_storage` 不会迁移或改写现有 RTC；当前诊断仍读取原始日历。深睡计时使用 ESP 内部 RTC 时基，无需外部 RTC 报警线。

尚未实测深睡电流、电池续航或低电量阈值。M1 关闭功放和屏幕内部高压，未进一步切断所有 PMIC 辅助电源轨。

验证范围和结果见 [验证记录](../validation.md)，后续计划见 [路线图](../roadmap.md)。
