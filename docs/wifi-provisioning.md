# Offline Wi-Fi setup

English | [简体中文](zh-CN/wifi-provisioning.md) · [Documentation](README.md)

Enter setup on first boot without valid Wi-Fi credentials, by holding KEY at least 2 seconds and releasing, or with token-authenticated `POST /api/wifi-provision` and `{}`. A saved-network connection/NTP failure does **not** automatically enter setup. Playback remains local. External-power Wi-Fi retries wait 60 seconds and defer around refresh/speech; configured connection timeouts bound each attempt. Web service returns when networking recovers.

## Procedure

1. The screen shows open `epaper-album-XXXXXX`, with the suffix from the device MAC.
2. Join using the QR scanner in phone **WLAN settings**. Wi-Fi QR payload: `WIFI:T:nopass;S:epaper-album-XXXXXX;;`. WeChat is not the Wi-Fi joining method.
3. Clients receive `192.168.7.x`; device/gateway/DNS is **192.168.7.60**, page `http://192.168.7.60/setup`.
4. Captive detection may open the page automatically. Otherwise scan the right HTTP QR with camera/WeChat after joining, or open the address manually. Phone/browser behavior varies; HTTPS is not intercepted.
5. Select a visible 2.4 GHz network or type a hidden SSID. The password field stays present. An existing network can retain a stored password by leaving it blank. Explicitly select open mode for password-free networks.
6. Save & connect. Success shows only confirmation, device LAN address and the **30-second** hotspot countdown. Return to the same home Wi-Fi to open the new address. Failure restores old SD settings and leaves the hotspot open.

The setup header has the same English/Chinese selector. Browser-local preferences for the setup IP and home LAN IP are independent. Choosing English does not change hotspot/QR data.

## Runtime and persistence

AP+STA retains the hotspot while scanning/connecting. Both share a radio; channel changes may briefly reconnect the phone. Setup pauses automatic refresh and time sync and prevents sleep. BOOT photo changes and unrelated settings are blocked; PWR shutdown still works. File APIs reject setup-mode access.

`/` serves setup in this mode. Unknown HTTP paths redirect (302) to the fixed setup URL. DHCP offers DNS and option 114; `/api/captive-portal` serves `application/captive+json`. DNS answers valid IN/A questions with the AP address; other types return empty answers.

The page uses status, POST/GET Wi-Fi scan and Wi-Fi settings APIs; protected requests still require `X-Album-Token`. Settings save atomically to the SD root. First setup enables Wi-Fi and NTP with existing mainland defaults if needed. A mounted SD with readable root settings and manifest is required to save; an empty photo library is allowed. Missing/corrupt configuration can display setup but cannot save.

Before rendering setup, persist the dirty-screen marker. Completion redraws the original photo; an interrupted boot uses existing display recovery. Album/photo configuration is not changed. After setup, USB/external-power keep-awake or battery scheduling resumes.

QR codes use the MIT Nayuki generator. Copyright remains in source. Neither QR contains the home Wi-Fi password.

## Display and success page

The 800×480 screen uses a blue title bar, white title and black/white instructions and QR codes. An 8-pixel spacing grid uses 24-pixel margins, two 360-pixel columns and a 32-pixel gutter. Each 232-pixel QR area and caption is centered by glyph bounds. Title, hotspot and bottom URL rows center as a whole; mixed scripts share a baseline. Version 0.18.0 adds concise English fixed labels alongside Chinese, independent of browser locale.

On success, hide scanning/form details, stop polling, retain address and countdown even after AP closure. Refresh within the grace period reconstructs success from the device's actual remaining duration. URL text is single-line at responsive 14–18 px. `provision_address.h` is the single address source for AP, redirects, DNS and QR. Home IP remains router-assigned.

Fonts are generated by `tools/provision_font.py`; the committed bitmap header builds without Pillow/fonts. Host tests check frame bounds/palette and recovery. Actual WLAN scanning, captive opening and screen appearance require phones/hardware; see [validation](validation.md).
