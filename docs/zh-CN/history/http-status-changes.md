## Wi-Fi独立设置与重连（0.14.0）

网络页新增Wi-Fi设置卡片，SSID为1–32字节，区分大小写，设备使用2.4 GHz网络。密码处理可选择保留原密码、设置新密码或无密码网络；新密码为空输入不代表保留，保留必须选择对应选项。新密码为8–63字节或64位十六进制密钥。密码框默认空，原密码不返回网页；提交接受后清空新密码。草稿在轮询中保留，保存Wi-Fi不提交其他设置的草稿。

`POST /api/wifi-settings` 接受 `{"schema_version":1,"ssid":"网络名称"}` 保留原密码；添加 `"password":"新密码"` 替换，`"password":""` 表示开放网络。只允许这些字段，拒绝重复键、无效类型和超长字节输入。沿用令牌、JSON内容类型、4096字节上限、202异步任务及队列冲突409，任务种类 `wifi-settings`。校时/Wi-Fi未启用时不可提交。不提供读取密码接口；`network.configured_ssid` 是已保存名称，`wifi_password_set` 仅表示有无密码。

先检查当前SD配置与运行配置一致，仅修改根配置network.ssid/password，完整验证、临时写入/读回/备份替换并更新缓存；随后应用任务停止HTTP、关闭原Wi-Fi并连接新网络，连接获得IP后重启HTTP。成功通过job状态succeeded确认，202本身不是保存或连接成功。更新校时配置副本和深睡指纹，但不重置下一次NTP时间，不修改相册位置或照片倒计时。

连接失败时用预先构造的原凭据请求恢复SD配置，再尝试连接原网络；任务failed中分别报告配置恢复和连接结果。若存储恢复也失败或原网络不可用，网页可能无法恢复，需要通过串口或读卡器纠正配置。恢复只覆盖本次SSID/密码修改，保留其他配置。该流程不是无条件的断电恢复保证，真实断电仍待验证。

提交前卡片说明切换会暂时断线、设备IP可能变化。电脑/手机需连接同一网络并打开新IP，串口输出新地址；页面只能自动轮询当前地址，不能从旧网络发现新网络的IP。HTTP继续用于局域网调试，凭据经当前HTTP连接提交，不新增外网服务。

## 校时设置保存（0.13.0）

“网络与时间”新增独立校时设置卡片，标题右上角保存/撤销，结果浮动提示。NTP服务器逐行输入（1–3个域名或IPv4地址，每个1–127字符，按填写顺序尝试），同步周期以小时输入（1–168小时），失败重试以分钟输入（1–1440分钟）。可输入小数，但换算后必须为整数秒。轮询不覆盖未保存草稿，保存其他设置不提交校时草稿。

`POST /api/time-settings` 接受 `{"schema_version":1,"servers":["ntp.aliyun.com","ntp1.aliyun.com"],"interval_seconds":86400,"retry_seconds":900}`。这三个设置必须同时提供；不允许空/重复服务器、URL、端口、未知字段、重复JSON键、非整数或越界间隔。沿用JSON内容类型、令牌、4096字节上限、串行队列和202/job_id状态查询，任务种类为 `time-settings`。校时停用或其他任务忙时返回409，语义错误由任务结果failed报告。

应用任务读取并校验当前根配置和相册清单，拒绝与运行中配置不一致的外部修改；只替换 `time.sync.servers/interval_seconds/retry_seconds`，保留Wi-Fi凭据、超时、RTC基准及其他字段。校验完整配置后，经临时写入、flush/fsync、读回比较和备份替换保存到SD根配置（默认 `/config.json`）。启动恢复根配置的 `.web-bak` 重命名窗口，更新缓存以支持现有配置回退。真实断电安全仍需实测。

保存后直接更新校时配置及深睡保留的配置指纹，从保存时刻按新周期安排下一次校时；不自动执行一次校时，使用“立即同步时间”可马上验证新服务器。相册、照片、播放位置和原倒计时不变。校时服务拥有独立配置副本，避免相册设置替换目录对象后留下悬空指针。

## 网络、时间与供电信息（0.12.0）

网络页展示Wi-Fi名称、IP、RSSI（dBm）、信道、USB主机状态，以及RTC型号、时间有效性、UTC基准和北京时间。校时信息包含配置中的NTP服务器顺序、同步周期、失败重试间隔、超时、最近尝试与结果、最近成功时间/服务器及下次自动校时。Wi-Fi密码不进入状态接口。

右上角“立即同步时间”调用 `POST /api/time-sync`，请求体严格为 `{}`，沿用 `Content-Type: application/json`、`X-Album-Token` 和4096字节上限。无令牌返回403，格式错误返回400/415，队列忙或校时停用返回409；接受返回202和job_id。请求沿用应用任务队列，HTTP任务不直接联网或写RTC；通过 `control.kind: "time-sync"` 和job_id/state/error查看处理结果。成功需NTP回复、RTC写入及读回验证、持久化完成；成功浮动提示自动隐藏，失败提示保留。不会更新相册配置或切换照片，原有相册时限按校时偏差重基准。

`network` 新增 `sync_enabled`、`ntp_servers`、`sync_interval_seconds`、`retry_seconds`、`sync_timeout_seconds`、`sync_attempted`、`sync_result`、`last_attempt_epoch`、`last_sync_epoch`、`last_sync_server`；已连接时新增 `ssid`、`rssi_dbm`、`channel`。时间戳是UTC秒，0表示没有可信记录。最近成功时间和服务器在album_state的time命名空间保存，最近尝试与错误仅属于本次启动。`rtc`、`environment`、`power` 新增 `chip`。

环境页将SHTC3温湿度（CRC校验）与AXP2101供电状态分卡展示，说明采样延迟、板上发热影响、USB主机和VBUS检测区别，以及电脑或USB外部供电保持在线、电池供电按计划深睡策略。电池标称3.7V来自用户描述；不将充电阶段推算为实际电流、容量或电量百分比。宽工作区两卡并排，窄屏上下排列。

设备连接电脑或USB外部供电、保持唤醒时，使用现有 SD 配置中的 Wi-Fi 凭据连接局域网并启动端口80的 HTTP 服务。串口会输出 `Status page: http://设备IP/`；同一局域网的电脑或手机打开这个地址即可。

- `GET /`：默认中文页面，适配手机和电脑，每5秒刷新。
- `GET /api/status`：只读 JSON 快照，不包含 Wi-Fi 密码或完整配置。
- `GET /albums`：照片管理页面，首页“打开照片管理”链接可进入，支持列表、预览、批量上传、下载和确认删除。

页面展示型号、固件、MAC、Flash/PSRAM、内部可用内存、运行时间、屏幕参数、IP、USB 主机状态、RTC与北京时间、下次校时、温湿度、外部供电、电池及充电阶段、相册和照片数量、当前照片、换图间隔、下次换图、SD容量与剩余空间。

## 内存展示（0.11.4）

设备概览分别展示内部 RAM、PSRAM 与 RTC RAM。内部 SRAM 硬件容量为512 KiB，RTC SRAM为16 KiB（ESP32-S3固定规格），PSRAM硬件容量由驱动读取。本机PSRAM为8 MiB。Flash单独标注为持久存储容量。

`GET /api/status` 的 `device` 增加以下字节字段，保留既有字段兼容性：

- `internal_sram_bytes`、`rtc_sram_bytes`：芯片硬件总容量，不是当前可用堆。
- `internal_heap_bytes`、`free_internal_bytes`、`min_free_internal_bytes`、`largest_free_internal_bytes`：内部8位可访问堆的总量、当前剩余、启动以来低水位、最大连续空闲块。
- `psram_bytes`、`psram_heap_bytes`、`free_psram_bytes`、`min_free_psram_bytes`、`largest_free_psram_bytes`：PSRAM硬件容量及对应堆统计。

内部堆按 `MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT`，外部堆按 `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT` 统计。堆总量使用 `heap_caps_get_total_size`，其他指标使用 `heap_caps_get_info`。硬件总容量部分用于代码、静态数据、系统预留及内存管理，不能全用于动态分配。低水位为各区域最低剩余之和，各区域可能在不同时间达到最低值；重启后重新统计。总剩余不保证能分配同样大小的一块内存。参见 [ESP-IDF 堆统计](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32s3/api-reference/system/mem_alloc.html)。

小于1 MiB以KiB显示，其余沿用MiB/GiB；1 MiB等于1024 KiB。页面解释PSRAM用途、内部RAM限制及RTC RAM与外部RTC计时芯片的区别。统计随原有快照刷新，不新增后台任务或改变睡眠策略。

HTTP 和 NTP 共用 Wi-Fi 生命周期。连接电脑、充电器或充电宝时保留网络供页面访问，周期校时保持网络连接。仅用电池时停止 HTTP、关闭并释放 Wi-Fi，继续按原计划深睡。深睡时网页离线，客户端显示上次读取的数据。

网络或服务启动失败最多每60秒重试一次，不中断相册。Wi-Fi未启用或没有有效配置时不能启动页面；不额外创建 AP 或要求新的 SD 配置字段。

状态由应用任务采样，HTTP任务只读取互斥锁保护的 JSON副本，不访问可变播放队列或直接读传感器。刷屏和校时期间可能暂停采样，页面保留上一份状态。传感器、RTC、电源或SD读取失败显示不可用。充电阶段不代表已测得充电电流，不显示未经校准的电池容量。

页面支持相册控制；0.6.0 同时提供照片列表、上传、下载、删除及重新索引 API，接口和命令行工具见 [SD 照片文件接口](../http-files.md)。实现基于 [ESP-IDF HTTP Server](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32s3/api-reference/protocols/esp_http_server.html)，不使用外部CDN资源。

已深睡时先按 KEY 唤醒，再连接电脑使用页面；USB深睡边界见 [USB状态](../usb-power.md)。IP由路由器分配，可能在重启后变化。


## 相册控制

- **下一张照片**：提交换图命令，完整刷新一般约30秒。成功后从刷新完成时刻开始计算下一次轮播间隔。位置使用原有NVS持久化，不修改相册清单。
- **选择相册**：勾选参与轮播的相册，可以多选，至少选一个。只展示现有清单的ID，不通过网页添加目录。所选相册若总计没有可索引照片，拒绝保存。
- **轮播间隔**：整数秒，120–604800（7天）；保存后统一应用到所选相册，重新开始完整停留时间。未选相册保留原间隔。顺序/随机、相册策略和其他字段保持原设置。
- **保存到SD卡并应用**：写入根配置指定的相册清单，默认 `/albums/albums.json`；根 `/config.json` 中的Wi-Fi、时间和其他配置保留。当前相册仍选中时保持当前屏幕；取消当前相册则显示所选相册中的下一张。重新开机仍使用保存后的选择和间隔。

HTTP任务仅接收命令，应用任务串行执行SD校验/索引/保存和显示。一次只接受一条控制命令，执行期间返回409，页面禁用重复提交；状态接口继续读取上次快照。设置先解析、验证并建立新索引，然后写同目录 `.web-tmp`，flush/fsync、读回检查，旧文件改名为 `.web-bak` 后安装新文件；启动时若主文件缺失，则从备份恢复。FAT文件系统在真实断电下的原子性尚未验收，备份不等于断电安全保证。

`POST /api/next` 接受 `{}`；`POST /api/settings` 接受 `{"schema_version":1,"album_ids":["相册ID"],"interval_seconds":900}`。均要求 `Content-Type: application/json` 和 `X-Album-Token`（来自状态接口 `control.token`，每次启动变化），请求上限4096字节。令牌和自定义头用于防止其他网页直接发起控制，不是用户登录认证。设备不开放跨域读取。

命令接受返回202与 `job_id`；通过状态接口的 `control.job_id/state/error/busy` 查看 queued/running/succeeded/failed。202仅代表已接受，不能当作SD已保存或刷屏已完成。解析/存储失败不改变原配置与播放；若配置已保存但显示或NVS更新失败，错误中会注明设置已保存。HTTP保留最新一项命令结果，重启清空结果。

0.8.0 起页面采用统一 Header、两级操作菜单与独立工作区，导航和响应式栅格见 [Web 控制台布局](../web-layout.md)。

## 独立设置保存（0.11.0）

`POST /api/settings` 保留原先同时提交 `album_ids` 与 `interval_seconds` 的兼容性，也支持只提交其中一项（连同 `schema_version:1`）。至少提供一项，不允许空相册列表、未知/重复ID或非法间隔。

- 仅 `album_ids`：更新启用相册，保留默认间隔以及每个相册的现有间隔。
- 仅 `interval_seconds`：更新默认间隔及已启用相册的间隔，保持启用选择及停用相册的间隔。

两种方式均沿用完整配置校验、备份/临时文件替换、索引重建与异步任务查询。页面两张卡片分别保存和撤销；另一张卡片的未保存草稿保持原样。换图操作位于侧栏底部。

## 网络设置入口（0.14.1）

Wi-Fi 与校时配置通过“网络与时间”页对应状态卡片右上角的设置按钮打开弹窗。独立保存、输入校验与原接口不变；保存完成自动关闭并提示结果。关闭不会保存，未提交内容保留在本页面，撤销恢复设备当前值。离线或设备忙碌时禁用设置入口。播放设置使用两张摘要卡片，分别从右上角设置入口打开独立弹窗。

0.14.2：设置弹窗只保留一个标题，关闭图标无外框；撤销和保存移至底部右侧。Esc 和遮罩不关闭弹窗。

0.14.3：Wi-Fi 操作归到 Wi-Fi 网络卡片，校时操作归到 RTC 与网络校时卡片；各卡片提供刷新，网络页顶部不再放按钮。

0.14.4：播放设置卡片只展示当前已保存值；相册选择和停留间隔在独立弹窗编辑，撤销和保存位于底部右侧。保存成功后更新摘要并关闭弹窗，另一份草稿保留。

### 状态快照年龄（0.14.8）

GET /api/status 的成功响应新增 X-Status-Age-Ms 头，值为非负整数毫秒，表示从RTC读取完成至发送状态响应前经过的单调时间。年龄与JSON快照在同一锁内取得，JSON结构不变。客户端可用rtc.calendar加快照年龄估计设备当前时间，结合本地单调计时在两次状态轮询间更新显示；RTC valid或utc为false时不显示推算时间。
