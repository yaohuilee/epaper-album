# 整点与半点报时（确认设计）

[文档目录](../README.md) · [后续计划](../roadmap.md)

2026-10-13确认，0.15.0实现。本文保留设计依据；实际设置、API和资源安装见[报时说明](../announcement.md)，验收证据见[验证摘要](../validation.md)。

## 已确认的行为

- 以设备显示时间为准，每小时00分和30分报时，两者可分别开关。
- 整点共5声，半点共3声，每秒一声；最后一声不同，**起音落在准确的整点/半点**。这意味着整点第一声提前4秒、半点提前2秒，不是提前5秒/3秒；该取舍已由用户确认。
- 最后一声结束后静默1秒，说“现在时刻”；这句话结束后静默1秒，说“X点整”或“X点三十分”。
- 普通话女中音，温暖、饱满、清晰，同一声线和语速。
- **多个暂停播报时段独立设置，不联动相册夜间暂停。**
- 暂停判断按目标报时时刻T执行；06:00恢复时，允许06:00整点报时的滴声从05:59:56开始。该边界已由用户确认。
- 时间短句结束后静默1秒，再播报“温度XX摄氏度，湿度百分之XX”。
- 报时、倒计时和排队提示不刷新墨水屏，屏幕继续保留照片；运行提示仅在Web展示。

第一阶段包含报时、温湿度播报、提示音、音量、多段暂停时段及网页试听。活动检测和按键重新分配暂不实现。保留KEY诊断/配网和BOOT换图的现有行为。

## 时间线

T表示目标整点/半点，与Header设备时间同源。小时从T锁定，不在后续语音开始时重新取值；24小时制，00点读“零点”，23点读“二十三点”，30分读“三十分”。

| 事件 | 整点 | 半点 |
|---|---|---|
| 普通短滴 | T−4、−3、−2、−1秒 | T−2、−1秒 |
| 特殊末滴起音 | T | T |
| “现在时刻”起音 | 末滴结束 + 1秒 | 末滴结束 + 1秒 |
| 时间短句起音 | “现在时刻”结束 + 1秒 | “现在时刻”结束 + 1秒 |
| 温湿度起音 | 时间短句结束 + 1秒 | 时间短句结束 + 1秒 |

滴声初始建议：普通1000Hz/100ms，末滴1500Hz/250ms，均带短淡入/淡出；频率、长度和响度试听后定稿，不靠大幅提高音量区分末滴。

例如末滴250ms、前缀800ms，则前缀在T+1.250秒开始，时间短句在T+3.050秒开始。实际以前缀有效样本数为准。三处1秒均指**声音结束到下一声音开始的静默**，不是起音点之间的间隔。裁掉文件多余尾部静音，使用PCM样本数控制静默，不用SD读取耗时或简单sleep计时。

## 语音资源与声线

建议先制作“现在时刻”“十点整”“十点三十分”及一段完整温湿度播报供试听，真机确认后再批量生产。整句短语保留完整韵律，不拼接数字、“点”和“三十分”：

- `now.wav`：现在时刻。
- `hour_00.wav`…`hour_23.wav`：24个整点短句。
- `half_00.wav`…`half_23.wav`：24个半点短句。
- 滴声由代码生成。

时间部分共49个WAV，温湿度资源另外统计；初选24kHz、16位小端PCM、单声道，统一响度和峰值余量。按48句平均2秒、前缀1秒估算，原始数据约4.66MB十进制容量；实际以资源清单为准。女中音的饱满感通过声线、语速和等响处理获得，不简单降低音调或过度增强低频；小扬声器的效果需现场试听。

资源放在`/audio/zh-CN/alto-v1/`，附清单记录文本、有效样本数、格式、长度、SHA-256和来源/许可。只预加载本次所需的时间和温湿度片段，不将全套资源常驻RAM。

生成工具和声线尚未选定，先核实生成音频的公开再分发、商业使用和归属要求。代码MIT不自动覆盖声线、模型或音频许可；完整资源包许可单独记录，不使用来源不明的真人克隆声线。声线试听通过后再生成资源，设备运行时不依赖在线TTS或Wi-Fi。

## 温湿度播报

完整示例：滴声 → 静默1秒 → “现在时刻” → 静默1秒 → “十点整” → 静默1秒 → “温度二十六点五摄氏度，湿度百分之六十二”。温度与湿度之间建议自然停顿约300ms，不再增加一整秒；此语感先试听确认。

建议沿用已有预留精度：温度1位小数、湿度整数，四舍五入后播报；温度小数为0时省略“点零”，负温度用“零下”，四舍五入得到0时不播负零。示例为“零下三点二摄氏度”和“湿度百分之六十二”，湿度单位不重复读。若希望温度也使用整数，可在Review后固定精度；本阶段不增加过多高级调节项。

在准备阶段、功放开启前对SHTC3进行一次新测量并校验CRC，锁定本次温湿度快照，避免板卡自热和前后两次采样不一致。环境值来自设备附近传感器，不读取电脑或天气数据，不使用网页中旧的缓存值。到环境播报时采样年龄建议不超过30秒，超过则省略环境部分并记录原因，不为补测打乱准点序列。

SHTC3测量失败、CRC错误或值不合法时仍正常报时间，1秒后说“温湿度数据暂不可用”，不播错误数值。资源缺失时记录环境段错误，保留可用的时间播报；不能为环境资源问题使相册启动失败。资源检查在滴声开始前完成。

时间短句继续用完整句。温湿度值变化，不为每个小数值生成完整句：追加同声线的“温度”“摄氏度”“湿度百分之”“零下”“点”、数字/整数片段及异常提示；按明确的中文数字规则组成数值。数字库存覆盖驱动允许值及四舍五入后的边界，避免拼接成“二六”而不是“二十六”。片段制作时匹配韵律和响度，以完整环境句试听验收；总文件数量和容量需重新计算，不能继续把49文件当完整资源包。

## 硬件与模块

当前扬声器/ES8311链路在硬件探测中通过三音测试，0.15.0增加正式音频播放器。GPIO14/15/16/17为MCLK/BCLK/WS/TX，GPIO7为功放使能，ES7210与双麦暂不参与生产报时。

早期探测使用24kHz、6.144MHz MCLK和32位双槽I2S，正式实现优先复验该时钟组合。WAV单声道16位与总线槽格式分离，按DAC有效槽转换，需验证电源、MCLK、增益和启停顺序；不能把探测脚本直接当正式驱动。

| 模块 | 职责 |
|---|---|
| 音频设备层 | ES8311、I2S标准TX/DMA、功放、增益、静音和失败清理 |
| 资源层 | WAV/清单校验、当前片段预加载和资源包切换 |
| 报时服务 | 下次目标、静音、去重、准备/播放状态机、校时通知 |
| 可测试调度核心 | 注入时钟，验证边界、时间跳变和遗漏事件 |
| 应用协调层 | 睡眠期限、长任务准入、锁及报时优先级 |
| Web与配置 | 独立设置、状态、试听及网络资源安装 |

使用[ESP-IDF v5.5.3 I2S标准模式新驱动](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32s3/api-reference/peripherals/i2s.html)，不混用legacy驱动。将本次滴声、静默、语音组成连续PCM时间线存入PSRAM，内部DMA/转换缓冲初始预算不超过32KiB，实施时检查可用内部堆与最大连续块，不能直接假设PSRAM适合DMA。

独立音频任务依据单调时钟和输出样本运行；回调不读SD、访问I2C或联网。提前初始化、预送静音，并观察RTC秒跳变，将目标映射到单调时钟。DAC/DMA/功放的声学延迟仍待实测。不能仅用“写入DMA”的时间戳证明实际声响落在T。音频I2C与RTC/环境读取统一互斥，避免当前单线程设备访问扩展后发生竞争。

## 调度、深睡、校时与去重

状态机建议：`idle → preparing → armed → beeping → prefix → time_phrase → environment_phrase → completed`，另有`disabled/muted/skipped/error/testing`。

1. 时间有效时计算下个启用的00/30分目标T，过滤静音与配网模式。
2. 提前10秒准备：重读RTC并核对系统时间、加载资源、读取并锁定温湿度、准备硬件。整点/半点有效声音仍从T−4/T−2开始。
3. 从墙上时间映射到单调时钟；普通NTP校时避开准备/播放窗口。尚未开始时遇时间修正，取消旧目标并重新计算；已播放时不改变节拍或语句，普通校时延后。
4. 电池睡眠期限取相册、校时、报时目标前30秒的最早值，分段复核外部RTC，留出启动余量。准备与播放期间保持唤醒，结束关闭功放/I2S，再恢复原供电策略。

**不补播错过的报时。** 开机、准备失败或任务忙错过起点就跳过，不在整点过去几十秒后补倒计时；第一阶段不采用旧预留的60秒迟到宽限。资源或时间无效时不输出半截序列，音频故障不能阻止相册启动。

同一UTC半小时槽最多尝试一次，开始前持久标记，深睡同时保留快速状态，重启不重复；持久化失败跳过。最高已处理槽防止时钟回拨重播，前跳跳过的槽不补。误校到未来再纠正可能导致较长抑制，状态需明确，去重重置必须由用户主动确认。

## 与长任务的协作

现有主流程含阻塞的刷屏、联网和配置处理，仅加`due()`分支不够。音频资源预载完成后不再依赖SD，准备/播放期间不启动新刷新，不卸载SD。

长任务准入条件：距报时准备的剩余时间大于该操作的有界最坏耗时。当前屏幕单次BUSY上限45秒且有多阶段等待，文件传输预算约60秒，不能把实测30秒当上限。前期保守保护窗口可能达到约110秒，实施时按全部阶段预算细化；这不是持续播放110秒，也不是关闭HTTP。

预算不足时自动换图、校时延后；手动换图合并为一个待处理请求，报时结束后执行；“即将报时，换图将在报时后执行”只显示在Web按钮或浮动提示中。实体BOOT操作不产生临时屏幕提示，音频也不为此添加额外提示音。墨水屏不展示秒级倒计时、音量滑块、报时状态或短暂通知。未开始的上传/配置操作返回可重试409和原因，网页保留文件选择；已开始的事务不强行中断。异常长任务超出预算时跳过报时，不硬切屏幕电源。

配网模式不自动报时。已开始播放时，配网请求延后至结束；软睡眠同样延后，PWR硬件关机仍可立即中断。报时不改相册选择、顺序或间隔；若刷新被延后，从实际刷新完成继续按原规则计时。

## 配置与多个暂停播报时段

报时配置保存在SD根`config.json`，相册清单的`night_pause`不变。示例配置：

```json
"announcement": {
  "enabled": false,
  "minutes": [0, 30],
  "volume_percent": 40,
  "pause_periods": [
    {"id": "night", "name": "夜间", "enabled": true, "start": "22:00", "end": "06:00"},
    {"id": "lunch", "name": "午休", "enabled": false, "start": "12:00", "end": "14:00"}
  ],
  "audio_root": "/audio/zh-CN",
  "voice_pack": "alto-v1",
  "include_temperature": true,
  "include_humidity": true,
  "temperature_decimals": 1,
  "humidity_decimals": 0,
  "max_lateness_seconds": 0,
  "catch_up_missed": false
}
```

默认报时关闭；音量建议40%，0为静音，不对应已校准声压。整点/半点至少选一项，只支持0/30。暂停时段可添加、编辑、删除和逐条启停，建议最多8段，夜间初值22:00–06:00，午休示例12:00–14:00默认停用；数组为空表示不按时段暂停。每条有稳定ID和名称，开始早于结束为当天，晚于结束为跨午夜，相同拒绝；网页每15分钟一档，旧合法分钟值保留。每天重复，不增加星期/节假日规则。

命中任一启用时段即暂停，多个时段取并集，重叠和相邻时段合并用于计算下一次可报时目标。跨午夜时段拆成当天末尾与次日开头计算，不能只比较字符串或依次看单条结束时间；全天被并集覆盖时不安排自动播报定时唤醒，并在Web显示“全天暂停”。温湿度跟随整场播报一同暂停，不单独在静音时段响起。

按**目标T**判断暂停，区间含开始、不含结束，不按倒计时起点判断。用户已确认：暂停22:00–06:00时，22:00不报，06:00允许整场播报，5声倒计时从05:59:56开始，特殊末滴在06:00:00起音。多个时段使用相同规则；若T同时命中另一启用时段，则仍暂停。半点报时允许时，3声倒计时从T前2秒开始。

原模板已预留`quiet_hours`单段静音（22:00–08:00）、温湿度播报和60秒宽限。迁移时将单段静音映射为一条暂停时段，保留原时间和开关；未修改旧配置不强行改成06:00。新保存使用`pause_periods`并移除旧字段；两种字段同时存在且不一致时提示修复，不静默选择一方。温湿度选项在本阶段实现，保留已有合法精度；迟到补播仍不启用，迁移时明确提示该预留选项的变化。报时子配置错误单独报告，不使相册整体停止。

## Web与音频部署

左侧设备管理增加“声音与报时”，不超过二级菜单。状态、报时设置、暂停播报时段三张卡片，设置通过弹窗编辑，撤销/保存在底部右侧，结果浮动提示。

报时设置含总开关、整点/半点、音量滑块及0–100数值，并放置试听按钮；暂停播报设置用多行时段列表，提供名称、独立Switch、起止时间和添加/删除。两类设置单独保存，撤销只恢复各自草稿。状态含资源就绪、声线、当前阶段、下次目标/倒计时、最近结果及跳过原因。使用设备时间。

提供“试听整点”“试听半点”，播放含温湿度的完整序列，明确显示立即播放声音。试听使用当前弹窗里的音量草稿，无需先保存，也不写入SD；完成后恢复已保存音量。滑块拖动不自动发声，0音量时显示静音并禁止无声试听。主动试听可绕过自动静音，但不抢占即将到来的报时；试听末滴无准点含义，小时取试听启动快照，不改自动去重标记。KEY等实体按键不重新分配。

建议API：`POST /api/announcement-settings`、`POST /api/announcement-pause-settings`、`POST /api/announcement-test`，复用令牌/异步任务协议；试听请求可传当前草稿音量与整点/半点类型，只影响本次试听。状态接口扩展`announcement`字段，包含命中的暂停时段、环境读数有效性与采样时间。

现有照片API只接受BMP，不能上传WAV。需要专用受限音频安装API和桌面工具，避免取SD卡：逐文件写暂存包，只允许固定音频目录与已知文件名，验证资源清单要求的全部时间/环境文件、WAV格式、长度上限、清单和哈希后原子启用；失败保留旧包。第一阶段Web只展示资源状态，资源管理UI后续增加。音频更新不与准备/播放并发，也不能暴露根配置或任意SD文件。

## 实施与验收

| 阶段 | Review/验收内容 |
|---|---|
| 声线样例 | 时间样例及完整环境句试听，真机女中音、语速、响度，来源和再分发许可 |
| 播放链路 | 两种滴声、WAV、三处1秒静默、0/40/100音量、功放启停及无明显爆音 |
| 桌面调度 | 00/30分、跨天/月末/闰日、多段/重叠/相邻/全天暂停、开始/结束边界、睡醒/重启、前跳回拨、去重写入失败 |
| Web与资源 | 独立保存、音量草稿试听、旧单段静音迁移、旧分钟值、传感器/数值与资源异常、上传失败旧包不变 |
| 真机协作 | 整点5声/半点3声、末滴不同、正确目标小时、相册/上传/NTP冲突、配网、电池提前醒和结束深睡 |

静默长度用PCM样本数验收；末滴对T的初始实际起音误差目标为100ms以内，不能只凭串口日志宣布达到。无外部仪器时用录音验证相对节拍和间隔，绝对准点误差保留为待测，必要时专门使用设备麦克风采样验收而不启用活动检测。

活动检测后续独立Review；声音能量不等于有人，持续麦克风采样与深睡有功耗冲突，自动报时自身声音必须排除。旧设计中的低电量阈值仍等待实测。
